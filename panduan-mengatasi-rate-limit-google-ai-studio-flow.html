1. Memahami 3 Metrik Limit: RPM, RPD, dan TPM

Ketika Anda membuat aplikasi atau alur kerja otomatisasi di Google AI Studio, Google membatasi konsumsi API melalui tiga parameter utama:

  • RPM (Requests Per Minute): Jumlah panggilan request API maksimal yang boleh dikirimkan dalam 1 menit (misalnya 15 RPM).
  • TPM (Tokens Per Minute): Jumlah total token (input + output teks/gambar) yang diproses dalam 1 menit (misalnya 1.000.000 TPM).
  • RPD (Requests Per Day): Batas total panggilan request dalam kurun waktu 24 jam.

2. Penyebab Utama Error 429 di Google Flow & Studio

Dalam alur kerja otomatisasi (*agentic workflows* atau multi-step prompt chaining), Error 429 biasanya dipicu oleh:

⚠️ Bottleneck Penyebab Rate Limit

1. Looping Script Tanpa Delay: Script otomatisasi menembak endpoint Google tanpa jeda waktu (*exponential backoff*).
2. Input Dokumen Raksasa Berulang: Mengirimkan file PDF 500 halaman di setiap percakapan tanpa menggunakan cache.
3. Kapasitas Storage Penuh: Gagal menyimpan data output ke Google Drive karena kuota akun gratis 15 GB sudah habis.

3. Trik #1: Aktifkan Context Caching untuk Memangkas Token

Jika Anda memiliki panduan instruksi sistem (*System Prompt*) atau dokumen referensi yang sama dan dipanggil berkali-kali oleh bot Anda, gunakan fitur Context Caching:

Google akan menyimpan token dokumen tersebut di memori server selama durasi waktu tertentu (*TTL*). Hasilnya:

  • Menghemat konsumsi token per menit (*TPM*) hingga 75%.
  • Mempercepat waktu respon inferensi hingga 3x lebih kilat.

4. Trik #2: Gunakan Structured Outputs (JSON Schema)

Jangan biarkan AI menghasilkan teks pembuka atau penutup yang tidak perlu (seperti "Tentu, berikut adalah hasil analisis saya...") yang membuang kuota output token.

Gunakan parameter response_schema dengan tipe MIME application/json agar model langsung mengembalikan data mentah dalam format JSON ringkas yang siap diproses script Anda.

5. Trik #3: Terapkan Model Routing (Flash vs Pro Tier)

Jangan gunakan model *Gemini 3.1 Pro* untuk semua tugas ringan. Pisahkan alur kerja:

  • Task Ringan (Ekstraksi data, filtering teks, klasifikasi sentimen): Gunakan Gemini 3.8 Flash yang memiliki RPM/TPM sangat besar.
  • Task Berat (Sintesis multi-sumber, refactoring kode, penalaran logika matematis): Alihkan ke Gemini 3.1 Pro.
